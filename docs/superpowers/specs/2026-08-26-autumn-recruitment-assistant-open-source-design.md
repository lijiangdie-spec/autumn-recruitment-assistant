# 秋招助手开源化设计

## 1. 目标与成功标准

把现有“自动简历撰写 + 秋招岗位作战台”整理成可公开分享的本地优先项目“秋招助手”，同时确保当前私人工作区、数据库、岗位文件夹、简历素材库和启动方式不被迁移、覆盖或破坏。

成功标准：

- 公开仓库不包含姓名、联系方式、照片、教育/项目/实习、岗位偏好、个人评分、投递记录、简历、数据库、浏览器登录态、本机绝对路径或私人文档 URL。
- Windows 与 macOS 用户可完成安装体检、首次引导、岗位同步、个性化筛选、投递管理、三种素材入库及一页简历生成。
- Codex CLI 与 Claude Code CLI 共用一套任务、JSON Schema 和渲染链路；代理只能读取明确授权的目录，不能直接修改素材库。
- 岗位网站只发布公开岗位字段。朋友本地拉取同一版本的岗位 feed，各自的偏好、评分、投递和简历始终留在本机。
- 你的现有系统只接受一个默认关闭的发布桥接；公开版未通过回归测试前不启用，也不改变任何既有默认行为。

## 2. 产品与仓库边界

### 2.1 隔离策略

在 `open-source/autumn-recruitment-assistant` 建立全新 Git 仓库，从现有实现中只复制经审计的通用源码和视觉资产。不得在当前总目录或 `autumn-recruitment` 私人应用目录初始化 Git，也不得复制现有 `data/`、岗位目录、`outputs/`、`通用简历/` 或真实素材库。

公开仓库保留一个本地 Next.js 应用，并新增：

- `skills/resume-writer/`：简历技能的唯一规范源；
- `.agents/skills/resume-writer/` 与 `.claude/skills/resume-writer/`：指向规范源的轻量入口，不复制个人数据；
- `site/`：静态岗位网站与版本化 feed；
- `scripts/`：跨平台安装体检、敏感信息扫描、feed 生成/校验与发布脚本。

不拆成多仓或云端服务。首发许可证为 0BSD，项目名称为“秋招助手”，默认仓库 slug 为 `autumn-recruitment-assistant`。

### 2.2 本地数据目录

运行时数据永远位于代码仓库之外：

- Windows：`%LOCALAPPDATA%\秋招助手`；
- macOS：`~/Library/Application Support/秋招助手`；
- 高级用户可通过 `AUTUMN_ASSISTANT_DATA_ROOT` 覆盖。

目录包含 `profile.json`、`preferences.json`、`materials/`、`resumes/`、`applications/`、SQLite 数据库、导入缓存与备份。应用启动时拒绝把数据根目录解析到源码仓库内部；所有写入采用临时文件 + 原子替换。

## 3. 首次引导与个人资料

首次运行进入可中断、自动保存的引导，而不是直接进入空看板：

1. **环境体检**：检测 Node、Codex/Claude Code、登录状态、XeLaTeX、PDF 工具、可写数据目录和浏览器；缺少可选依赖时给出明确降级能力。
2. **基本资料**：姓名、联系方式、教育、技能、证书和求职阶段。
3. **素材入库**：支持结构化访谈、旧简历导入、本地代码仓库分析；写进素材库不代表一定写进简历。
4. **岗位偏好**：用户自定义岗位方向、城市、届别/用工类型、硬门槛、排除项、评分维度、权重和推荐阈值。公开版不内置金融、量化、2027 届、六级、城市或 75 分线预设。
5. **简历偏好**：模板、格式、主题色、照片、输出目录、默认代理和岗位 feed 地址。

结构化 JSON 是事实源；DOCX/PDF 是可再生导出物。旧简历只提取可追溯事实，缺失字段保留待确认。代码仓库分析可自动提取技术栈、架构和代码证据，但个人角色、动机、业务成果及数字必须由用户确认。每次确认记录来源、时间和状态，未确认事实不得进入简历。

## 4. 双代理与简历流水线

定义统一 `AgentAdapter`：

- `doctor()` 返回安装、版本和认证状态；
- `runStructuredTask({ task, schema, readRoots, timeout })` 返回已通过 Schema 校验的结果和可展示错误。

Codex 适配器使用非交互 `codex exec`、临时会话、只读 sandbox 和输出 Schema；Claude Code 适配器使用 `claude --print --json-schema`，禁止写工具，仅允许读取任务需要的目录。两者共用提示模板和数据契约；用户选择哪一个就使用哪一个，失败时不静默切换或重复计费。

旧简历由应用先提取文本后再交给代理；代码仓库分析只允许读取用户显式选择的路径，不运行项目代码。代理只返回草稿，应用负责 Zod/JSON Schema 校验、事实引用检查和原子写入。

岗位简历必须由用户点击生成。生成流程为：读取 JD 与已确认素材 → 结构化选材/改写 → 渲染 PDF 或 Word → 检查单页、占位符、乱码、可提取文本、裁切与预览 → 成功后原子替换旧文件。文件名、照片、基线简历、模板和输出位置全部来自用户配置。岗位同步不会自动生成或重写简历；JD 变化只标记“需要复核”。

## 5. 岗位网站与同步协议

你的 Excel、腾讯文档和现有采集器继续作为上游。发布桥接从规范化岗位数据构建白名单快照，不允许通过“删除少数字段”的方式序列化数据库实体。

公开 feed 由两层组成：

- `manifest.json`：`schemaVersion`、`releaseId`、`generatedAt`、岗位数、SHA-256、数据文件 URL；
- `feeds/<releaseId>.json`：稳定岗位 ID、公司、岗位、城市、届别/用工类型、发布日期、截止时间、公开 JD、来源/投递链接、来源名称、更新时间和内容哈希。

明确排除：个人备注、个人评分与覆盖、筛选结果、垃圾桶、投递状态/事件、简历、素材、联系方式、本机路径、导入文件路径、浏览器状态和内部错误日志。

每次本地更新成功后自动构建并发布新版本：生成 → Schema/唯一键/链接/哈希校验 → 上传不可变 feed → 更新 manifest → 从公网回读并核对哈希。只有远端校验通过的版本才声明为最新；失败保留上一版并进入带退避的重试队列。客户端按 `releaseId + sha256` 幂等同步，只增加或更新公开岗位，不覆盖任何本地个人字段。UI 显示本地版本、远端版本、上次成功时间和失败原因。

跨本机、GitHub 和朋友客户端无法形成单一数据库事务，因此一致性承诺定义为“可验证的版本一致 + 自动最终一致”：同一 `releaseId` 的 Excel 规范化快照、网站 feed 和已同步客户端必须具有相同哈希；网络或 GitHub 失败期间远端继续指向上一成功版本，本机明确显示“发布待重试”，不得把三端暂时不一致报告为成功。

静态网站展示公开岗位目录、搜索筛选、来源、更新时间和 feed 状态，不提供账号、云端简历、个人资料或网页后台编辑。

## 6. 兼容、测试与发布

### 6.1 私人系统兼容

发布桥接以功能开关和独立配置启用；未配置远端仓库时完全不执行。它只能读取规范化公开岗位并写自己的发布缓存，不能移动或重命名现有数据库、素材库、岗位文件夹和简历。启用前使用数据库副本和合成 feed 做回归；失败只影响发布状态，不删除或回滚私人数据。

### 6.2 测试

- 单元测试：配置校验、通用偏好评分、事实确认、路径边界、文件名、两个代理参数与结果解析、feed 白名单、Schema、哈希和幂等合并。
- 集成测试：全新用户引导、三种素材入库、Codex/Claude mock、简历生成失败保留旧文件、JD 变化只标记过期、feed 发布失败重试与客户端断点同步。
- E2E：Windows/macOS 的空数据首启、设置修改、岗位同步、投递看板、素材 CRUD、简历预览；真实私人数据库不得进入测试。
- 安全测试：邮箱/手机号/姓名/绝对路径/密钥/数据库/照片/个人素材扫描；仓库和构建产物均扫描，命中即阻止提交与发布。
- 视觉 QA：桌面与窄屏关键页面、空状态、引导流程、错误状态、简历全页渲染。

当前私人应用基线为 ESLint 通过；Vitest 31 个测试文件中 29 个通过，两个套件在 Windows 因既有 5–10 秒超时失败。公开版必须修复或合理调整这些超时，并在干净环境全绿，不能把现有不稳定性误判为新回归。

### 6.3 发布

GitHub Actions 在 Windows 与 macOS 上执行 lint、单元/集成测试、构建、敏感信息扫描和静态网站部署。README 提供五分钟启动、隐私模型、Codex/Claude Code 配置、依赖体检、数据备份/迁移及故障排查。仓库包含 0BSD、贡献指南、安全报告说明和合成示例。

GitHub 插件已连接，但不能创建新仓库；用户在发布阶段手动创建空的公开 `autumn-recruitment-assistant` 仓库并提供链接。之后由自动化完成首个提交、推送、CI 检查和网站发布；GitHub Pages 若需要首次启用，则由用户完成一次仓库设置确认。

## 7. 非目标与默认决策

- 不做云端多用户、登录、租户、云数据库或在线简历存储。
- 不做网页后台或 Excel/网站双向编辑；网站是本地上游数据的只读发布镜像。
- 不内置行业/岗位偏好预设；所有个人筛选从首次引导产生。
- 不在岗位同步时自动调用代理或生成简历。
- 不重写现有私人 Git 历史：当前目录及子项目尚未初始化 Git，公开仓库从净化后的新根目录开始干净历史。
